# Invention 1 — Implemented vs. Proposed

> Part of the Invention 1 Technical Disclosure Pack. See [README.md](./README.md) for scope and confidentiality notice.

This section answers the patent agent's question: *"which features are already implemented and which remain proposed."* Every "Implemented" claim cites the code that proves it; every "Proposed" claim cites the design document or placeholder that proposes it. Status is as of the repository state on 2026-08-24.

**Honest summary for claim drafting.** Invention 1 as titled has two halves:

1. **The digital governance layer linking real-time livestock management data to government oversight — IMPLEMENTED.** Farmers log operational data (milking, feeding, health, breeding, weights) on an offline-first mobile platform; database triggers and scheduled jobs aggregate it; government users see region-filterable herd, production, health, feed, compliance, grant-effectiveness, and data-quality analytics through audited, PII-stripped, role-gated read paths, plus a two-way farmer-feedback channel with AI triage.
2. **The subsidy-compliance coupling (compliance scores gating or triggering subsidy disbursement, and any machine link between the CAIN cooperative ledger and government systems) — PROPOSED ONLY.** The schema carries program-enrollment hooks and the government dashboard carries explicit "Coming Soon" placeholders for it, but no disbursement, gating, or coop-to-government data path exists in code.

This distinction matters for the patent strategy: implemented subject matter supports actual reduction to practice; proposed subject matter can still be claimed via constructive reduction to practice (an enabling written description), but the specification must be written prospectively for those elements.
